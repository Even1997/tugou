# 模块全局应用验收

## 行为

- 每个模块独立设置“应用全局”。开启后自动加入当前工程全部配方；关闭后由各配方勾选，公共画风也遵循此规则。
- 配方显示全局模块的选中状态及“全局”标记；关闭全局时保留原来各配方的手动选择。
- 新建普通模块默认关闭全局；旧工程、示例和参考图分析保留原来的画风默认全局行为。修改模块类别不切换应用范围。
- 预览、生成指纹和发送画布共用模块选择规则；去重、排除空正文，画风仍放在内容模块之后。
- 已存在画布保留显式节点与连线。全局开关不增删已有节点，也不产生内容“有新版”的误报；正文变更继续走原有引用更新。

## 验证

- `node --test tests/studio-model.test.mjs tests/studio-module-sync.test.mjs`：17/17。
- TypeScript `--noEmit`、Next.js 生产构建、Windows x64 桌面打包通过。
- 在隔离工程运行打包产物，界面实测：
  - 公共画风关闭后从未选择它的配方提示词消失；手动勾选后恢复。
  - 人物身份设为全局后，在双人人物、花园背景两个配方均出现一次；背景配方不混入未勾选的局部画风。
  - 背景配方发送画布后得到背景、人物两个文本节点及一个图片节点，引用状态“已同步”。
  - 全局设置落盘，刷新后保留；关闭人物全局后原人物配方的手动选择保留；撤销恢复开启，重做恢复关闭。
  - 1280 宽深色、1024 宽浅色布局检查通过，开关与配方操作无重叠。
- 截图：`global-modules-dark.png`、`global-modules-light.png`（隔离工程的测试配置）。
- 新桌面运行证据：`global-modules-desktop.json`。更新前工程备份位于 `.tools/before-global-modules`；原工程内容除显式全局布尔字段外保持一致。
- 初次测试服务连接现有桌面后端的命令被自动审批拦截，改用完全隔离的生产前端完成验收。没有调用真实模型或改变用户 API 配置。
