# 离线精细抠图试验：暂不接入

结论：三种自动trimap参数均未稳定解决原主体蒙版的错误，不应直接作为“精细抠图”发布。只在独立QA环境试验，现有桌面抠图运行库和用户素材未修改。

环境：`D:/CanvasStudioMattingQA/venv`，Python3.10；PyMatting1.1.16、numpy2.2.6、Pillow11.3.0、scipy1.15.3、numba0.68.0、llvmlite0.50.0。参考[官方示例](https://pymatting.github.io/examples.html)中的closed-form Alpha和多层前景估计，MIT许可证见[官方项目](https://github.com/pymatting/pymatting/blob/master/pyproject.toml)。不含新神经网络模型，也没有上传图片。

输入为上一批同组660×880人物、333×500人物与451×300宠物，RGB沿用原图，Alpha来自IS-Net。脚本 `desktop/tests/atelier-matting-proof.py` 当前保留第三种方案。输出在D盘独立results目录中，均检查白底和深色底。

| 自动trimap | 输出目录 | 实际观察 |
|---|---|---|
| 前景>240/255、背景<10/255，十字腐蚀2次 | results | 人物灰边仍在，衣物轮廓出现块状边缘 |
| 前景>253/255、背景<10/255，11×11腐蚀 | results-wide | 部分发丝灰边减少，但白色衣物和宠物眼睛等内部像素被误判半透明，不合格 |
| 0.5主体边界两侧各11×11腐蚀，仅边界未知 | results-boundary | 保护了衣物与眼睛，但原蒙版纳入的灰背景块仍存在，宠物轮廓块状残留明显，不合格 |

第三种方案三样本计算约0.446/0.140/0.208秒（不含进程启动/导入），已知前景的输出RGB字节全部与原图一致；这些数值只证明运行和保护机制，不证明画质。第一种记录的knownForegroundRGBUnchanged=false是float32/float64逐值比较不合适，后续改为实际PNG uint8断言，不能将该布尔值解释为人物颜色已改变。

当前问题不只是柔化边缘：IS-Net把部分背景判为主体，自动trimap进一步把它作为确定前景，后处理无法可靠纠正。下一步优先对比更合适的本地分割模型/人工边界约束，再评估局部matting；不要继续盲目提高阈值或收缩。必须另外验证原始Alpha、衣物/皮肤/眼睛保护、大图分块与取消、模型许可和实际资源开销，不能凭三张小图就接入100MP通道。

美术试验评分8.0/10，未达9.3，未接入产品。现有总体抠图美术仍沿用上一批8.8未通过的结论。没有因本试验新增产品依赖、入口或自动处理步骤。
