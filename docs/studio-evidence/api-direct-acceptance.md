# 本地桌面直连模型 API 验收

本次范围：平台和工程本地运行，图片分析和生成直接请求用户指定的模型 API，移除线上 MCP 依赖。不是本机部署图像模型。

## 已验证

- 配置仅有 API 地址、密钥、生成模型、视觉分析模型。MCP 客户端、工具发现、远端项目创建、任务分支、环境令牌读取及直接 SDK 依赖已删除。
- 配置白名单忽略旧 MCP 字段；旧 `mcp-tools` 操作返回 400，不产生外部请求。
- 本机模拟提供商收到 `/v1/models`、`/v1/images/generations`、`/v1/images/edits`；鉴权和多张参考图顺序已断言。视觉分析通过 `/chat/completions` 返回模块。
- 界面点生成后，素材由 4 份增加至 6 份，新增 V2/V3；2 个任务显示 completed，原 6 个图层不变。模拟服务返回已有示例图，没有调用收费模型。
- 最终桌面包运行 16 项测试：16 通过、0 失败；独立 TypeScript 检查、Next.js 生产构建与桌面主进程语法检查通过。
- 实际启动新 CanvasStudio.exe，主窗口标题为“图构 Studio · 模块化视觉创作”；`/studio` 与 `/api/settings` 返回 200；服务只监听 127.0.0.1:3418。
- 更新前后用户工程 SHA256 一致。工作区快捷方式已更新；数据继续使用 `%APPDATA%/CanvasStudio/projects`。
- 已修复 Next.js 的已知严重运行时依赖风险，版本为 16.4.2。下载经官方 npm 发布的 SHA512 校验值核验。来源：[Windows 漏洞公告](https://github.com/advisories/GHSA-p293-qw3h-jr36)。
- npm 审计仍有 7 项 shadcn 开发工具链的 high 告警；已检查相关包未进入桌面运行包。本次没有做开发工具链的破坏性降级或全仓库依赖重构。

## 尚未验证

- 用户尚未配置真实 API 密钥与模型；没有宣称真实出图成功。
- 当前新工作台支持 OpenAI 兼容 Images API 的直接图片返回。异步任务、Responses API 等其他供应商协议不在这次适配范围内；原无限画布保留其自身已有适配。
- 原画布与新工作台的模型设置仍各自管理；未来可统一交互，但不会把加密密钥为了同步而直接暴露给网页。
