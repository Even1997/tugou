# 已知 Alpha 合成基准

**当前解释（用户已澄清）：默认需求是识别并抠出主体，外围柔光按用户用途处理。本页保留原Alpha还原实验及原始分数，0/9不等于普通主体抠图0/9不可用，也不能作为其唯一发布门禁。柔光偏好不再待答。当前验收口径见 [主体抠图验收口径](atelier-cutout-criteria.md)。**

`desktop/tests/atelier-alpha-fixtures.py` 从现有情侣/花束透明素材及一张解析生成的半透明薄纱和细线图，分别合成浅色、深色、棋盘纹理背景，共9个输入。原Alpha保留为真值，素材缩到不超过1024像素。此为可重复的透明度压力样本，不是实拍人物Alpha数据集；原插画的柔光也属于保留目标。

在推理前设定内部筛查阈值：整体Alpha MAE≤0.03；真值Alpha在0.05–0.95区域的MAE≤0.12；真值>0.95的主体像素中预测>0.9占比≥97%；真值<0.01的背景中预测<0.05占比≥98%。这些是本项目实验筛查条件，不是行业质量标准。

### 资源诊断与采用决定

`atelier-matting-resources.ps1` 实际采样Windows GPU Process Memory与进程内存，31个采样点：专用显存占用最高11250.5MiB，共享GPU内存1442.4MiB，进程树工作集4711.6MiB，私有提交13707.2MiB。不同指标不可相加当作物理RAM。记录 `atelier-matting-fp16-resources.json`。300ms等待加CIM查询的离散采样可能漏掉瞬时峰值，也不代表活动编辑器共同运行验收。

ORT profile记录41条kernel事件，全部标记DirectML，没有CPU provider kernel事件；融合节点不能逐一对应原始ONNX算子，计时也不能当作纯GPU运算耗时。概要/原记录路径与哈希见 `atelier-matting-fp16-profile.json`。**没有证据支持“CPU回退导致高内存”，也未定位全部分配来源。** 初次采样仅捕获venv启动器导致0显存，属于无效资源证据；脚本已修正为启动器及实际解释器子进程，重新实测，并增加未捕获GPU计数即失败的断言。原错误记录留在QA目录，未作为通过依据。
