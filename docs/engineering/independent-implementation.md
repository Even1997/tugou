# 图构自主实现与替换计划

用户已明确：可以替换复用代码，以自己的产品需求和设计实现。展示清理不等于完成源码替换；当前版本仍保留原许可，不能改成“全自主代码”或直接换许可证。

用户最新明确：产品尚未上线，不做旧版与独立版之间的持续同步、双向更新或新增兼容层。旧版只作UI/行为参考，已有数据保留；已有手动一次性导入不扩展为长期同步。工作台模块与画布引用更新属于同一产品内部功能，继续保留。当前代码的旧版读取由手动导入入口触发，没有旧版文件监控或自动回写链路。

## 当前证据

独立云端四工具与原始图审阅/离线恢复已接入，最新验证见[云端验收](independent-cloud-tools-acceptance.md)。只验证本地模拟协议和像素处理，真实模型画质、Mac 与最终桌面更新仍待。以下来源统计为此前审计记录，不代表本批新增代码数量。

`node scripts/audit-source.cjs` 对本地上游共同基线、当前提交和工作区进行来源分类，明细在source-audit.json。这是内部工程审查，不是产品中的来源宣传。

- Go后端：130个运行时文件与基线相同、1个修改文件；属于优先替换范围。
- Web底座：192个运行时文件与基线相同、20个修改文件；现有画布、状态和媒体存储不能作为自主源码直接搬入新版本。
- 桌面入口2个、Studio API 17个、Studio界面76个文件是基线之后新增，需逐项检查来源和依赖，不能直接认定为独立原创或可重新许可。
- 画布桥接层直接引用旧画布store/types、图片存储和本地存储模块，必须连同接口边界一起替换。旧Go进程仍由桌面主进程启动。
- 已查45项直接安装的npm依赖许可字段；不是完整依赖合规审查。传递依赖、Go包、模型及数据条款仍需单独核对。许可证宽松的基础库可以在保留必要声明后继续使用，无需自行重造浏览器或图像解码库。

## 实施方式

在 `app/` 建立独立实现入口，以已批准的功能需求、数据格式和交互行为为规格。旧 `web/`、Go服务与桌面包暂保留作回退，不把其源码复制或重命名到新入口。新入口不导入旧实现，也不通过启动旧服务来掩盖尚未替换的功能。

本次参与者已经接触旧实现，因此不能把这个流程宣称为严格隔离的clean-room法律证明。来源审计、实现记录、依赖与许可核验必须保留；删除仓库历史或通过代码相似度检测均不能代替这些证据。

## 替换顺序与验收

| 阶段 | 实现范围 | 验证与完成定义 |
| --- | --- | --- |
| 1 本地底座 | 新桌面入口、共享模型连接、工程/素材存储、后台任务 | 单实例及窗口操作；密钥只在主进程加密保存；原子保存/故障恢复；取消/重启不重复收费；无需旧Go服务即可运行 |
| 2 提示词工作台 | 可扩展模块、配方、参考图职责、全局应用开关、引用版本 | 创建/编辑/删除/保存重开；引用过期提示和一键更新，冲突需明确选择；与画布共用配置和素材 |
| 3 无限画布 | 视口、节点/连线、拖放、生成与任务状态 | 单窗口融合；多选/移动/缩放/撤销；模块拖入、版本同步；实际API请求、错误/取消与入库闭环 |
| 4 图层编辑 | 图层/组/文字/形状、排版/透视、蒙版/选区、统一合成导出 | 原有已约定编辑能力不缩水；选择范围、撤销和重开一致；原分辨率与Alpha保护；代表工程全像素导出对照 |
| 5 图片处理 | 超分/抠图、修图笔刷、内容填充、调整层/特效、LUT/图案/批量 | 不移植已标注来源的算法代码；可用标准算法独立实现或经许可的组件；真图画质、失败/取消、显存/内存和大图测试 |
| 6 数据迁移与交付 | 旧工程只读导入、新格式输出、独立打包、原生窗口/缩放 | 旧工程/原素材/密钥不变；功能迁移报告；包内不含旧服务或受限源码；依赖清单、许可和源码来源审查通过后才能确定最终授权 |

每阶段完成后才切换相应入口；旧版只有在完整迁移、恢复及交付验证通过后才归档。原有视频/3D/完整Agent暂缓范围不变，当前替换不以新增这些能力代替图片工作流。

## 风险与交付门槛

- 供应商尺寸、视觉模型和异步能力问题与源码替换独立，重写不能让不支持2K的接口突然支持2K；保留真实验证限制。
- 图层渲染、发丝/薄纱、内容填充等需要效果验证，不能只通过类型检查或按钮存在就算完成。
- 现有源码规模较大，不能承诺通过几处删除就达成全量自主实现；没有逐模块实际证据前不给完成比例或全量工期。
- 分发旧版本期间保持旧许可。新版本最终授权要根据实际纳入的源码/依赖及权利归属确认，当前不自动改成闭源专有许可。
