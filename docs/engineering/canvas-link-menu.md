# 拉线节点选择白屏修复

问题发生在从节点拉线到画布空白处后：菜单使用只有 `id/type` 的临时对象过滤可连接类型。“生成台”的连接规则需要读取 `data.mode`，临时对象没有 `data`，导致未捕获的渲染异常，整个界面被卸载。

生产修复仅修改 `renderer/canvas.jsx` 的一行：候选节点由既有 `createNode` 工厂创建，包含与实际新建节点一致的配置。没有修改底层连接规则、工程格式或其他业务；临时候选不会写入文档或撤销历史。

## 验证

`app/test/canvas-link-menu-desktop.cjs` 在独立工程中使用实际 Electron 鼠标事件：修复前复现 `Cannot read properties of undefined (reading 'mode')`，修复后 18 项通过、渲染错误为零。

- 输出端拖到空白处弹出菜单，只列出可连接的生成类型；搜索选择后创建节点并连接到原节点。
- 输入端拖到空白处提供上游文字／图片等类型，连线方向正确。
- 创建节点和连线只增加一次撤销，撤销／重做完整。
- Esc 与点击空白可取消，后续普通新建不会遗留上一次连接。
- 已有节点之间直接连线正常，无效连接不写入工程。
- 菜单在深浅主题及 960×720 窗口中保持可见、不越界，原节点内容保留。
- 在不触发靠近边缘自动平移的拖线位置，打开／取消菜单前后 revision、dirty 和撤销状态一致。

证据位于 `app/test-results/canvas-link-menu/`：`before-report.json`、`before-white.png`、`report.json`、`output-menu-dark.png`、`output-menu-light.png`。测试不打开用户工程、不调用图片生成或外部模型。

`prompts.test.cjs`、`workflow-nodes.test.cjs` 共 18 项逻辑回归通过；见同目录 `logic.log`。确认原白屏进程已退出后重新启动开发预览，MCP 连通并返回 149 命令；实际预览的 `ui.js`／`ui.css` 与上述验收构建逐字节一致。没有强制结束旧进程或操作用户的节点。
