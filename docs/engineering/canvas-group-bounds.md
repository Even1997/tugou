# 画布组合边框修复

## 原因与范围

原组合尺寸缺少测量时固定使用 230 × 200，而当前文本/图片卡片默认宽 300、生成台宽 400，长图高度还会随图片加载变化。组合创建后，普通拖动、缩放及异步内容测量未统一更新边框。

`app/core/canvas-groups.cjs` 的 `fitGroups` 统一节点尺寸与组合贴合计算；`app/renderer/canvas.jsx` 在提交修改、恢复节点及接收真实尺寸时同步边框；组内整理复用同一算法。MCP 创建组合沿用共享核心，实时显示通过相同测量流程校正。

边距保留左右/底部 24、顶部 48 个画布单位。根据成员节点当前边界重新计算组尺寸，支持四侧扩展与收紧；移动组原点时反向调整子节点坐标，因此节点画布绝对位置不变。拖动/缩放松手后统一贴合，手势期间不重定位组原点。不新增嵌套组合。节点连线、素材和项目内容不改动。

## 验证

- `canvas-groups.test.cjs`、`canvas-layout.test.cjs`、`workflow-nodes.test.cjs`：23 项通过，覆盖默认尺寸、实测尺寸、左右上下扩展与收紧、尺寸缩小、输入不可变、重复计算稳定性、解组位置及组内整理。
- `automation.test.cjs`、`canvas-view.test.cjs`：14 项通过，覆盖现有 MCP 分组/解组、批处理、节点尺寸及生成结果定位相关回归。
- `canvas-groups-desktop.cjs`：26 项通过，使用隔离 Electron 工程及真实 MCP，检查键盘组合、长图测量、鼠标向内/向外拖动、放大/缩小图片、收紧边框不移动其他节点、单步撤销重做、MCP 移动、30%/80%/140% 视口缩放、组内整理、深浅主题、保存重开与解组；渲染错误为零。报告和截图输出至 `app/test-results/canvas-groups/`。实际窗口启用了可见节点虚拟化，因此全组检查先切换概览；高倍率检查仅针对可见节点，不将屏幕外未挂载的节点误报为丢失。

检查未访问用户当前工程、未调用生图服务、未重启用户实例。测试运行于 Windows；macOS 原生窗口和用户原工程仍待确认。
