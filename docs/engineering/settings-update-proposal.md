# 土狗设置页与更新方案（待确认）

本轮只提出方案，尚未实现设置页或自动更新。

## 页面结构

左下角增加“设置”入口，打开独立设置面板，保留当前工程与编辑状态。复用现有表单、下拉、主题与弹层。左侧三项导航，右侧设置内容；基础选项即改即存，显示失败并恢复原值。

| 页面 | 第一版内容 |
| --- | --- |
| 通用 | 深色／浅色／跟随系统；启动时恢复上次工程；现有模型连接入口；MCP启用状态与接入入口 |
| 存储 | 显示并打开数据目录；缓存占用与清理缓存；明确区分缓存和工程原图、字体、模型，清理不删除创作数据 |
| 更新与关于 | 土狗Logo、版本号、更新日志、GitHub仓库；自动检查开关、上次检查时间、检查更新、下载进度、重启安装 |

第一版不加入账户同步、更新通道切换、自定义更新服务器、自动删除原图或数据目录迁移。模型连接继续复用已有供应商管理，不在设置页再建一套。

## 更新交互

- 默认后台自动检查，每天最多一次；设置中随时手动检查。发现新版本显示轻提示，不打断编辑。
- 默认由用户点击下载；可提供“自动下载更新”开关，默认关闭。安装始终由用户点击“重启并安装”。
- 状态明确区分：未检查、检查中、已是最新、有新版本、下载中、下载完成、失败可重试、不支持自动安装。网络错误不能显示为已是最新。
- 重启前处理未保存工程；生成、字体编译等任务仍在运行时暂缓安装并指出原因。保存失败、用户取消或任务未结束时不退出。
- 开发／解压预览版显示版本与发布页入口，并说明安装正式版后使用自动安装。不能以开发环境模拟测试宣称真实升级成功。

## 发布与实现

沿用现有Git remote指向的公开发布候选仓库 `Even1997/tugou`，最终以用户开源仓库为准。主进程使用 `electron-updater`，通过固定GitHub Releases源获得版本、安装包与校验元数据；前端只接收状态并发出检查、下载、安装请求，不提供任意下载地址或执行文件路径。发布令牌只在CI secrets中保存，不进入应用或源码。

Windows使用NSIS安装版；Mac需签名并提供DMG和更新用ZIP，按arm64/x64分别发布。GitHub Actions在明确发布tag后构建，Release附件包含安装包、blockmap和latest.yml／latest-mac.yml。日常提交不发布，预发布不推送给稳定版用户。

当前根目录VERSION为v0.8.1，app/package.json为0.1.0。实施前确定统一版本来源，并校验tag与包版本相等；本轮不擅自提升版本或打tag。

官方依据：[electron-builder v26自动更新](https://www.electron.build/v26/docs/features/auto-update/)。

## 验收与完成定义

- 设置持久化、重启恢复、深浅主题、键盘操作及窄窗口检查通过。
- 清理缓存前后原图、工程、字体及模型配置保持不变；失败反馈可恢复。
- 覆盖更新检查成功／无更新／断网／请求失败、下载进度／失败重试、未保存和运行任务阻止安装、重复点击去重。
- 在真实Windows安装版做A版本升级到B版本，重启后版本正确，用户数据、模型连接与MCP可用；Mac需另行实机验收。
- 无正式Release、签名或对应平台环境时标记待验，不能称自动更新已完成。
