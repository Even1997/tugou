# 图构 MCP 接入与验收

图构现在可以作为 MCP Server，供 AI 编辑正在运行的桌面工程。实现参考 FigCraft 的命令发现、实时文档、事务批处理与可视化反馈，使用官方 MCP TypeScript SDK 的 stdio 协议；没有复制它的代码或另建一套画布引擎。

## 启动与接入

1. 运行项目根目录的 `启动图构MCP.cmd`。如果已开着本轮新版的普通窗口，会直接在该窗口启用 MCP，保留未保存内容和撤销记录。升级前仍在运行的旧版需要先保存并重启一次。首次需要在窗口打开或新建工程，也可以由 MCP 的 `project.create` / `project.open` 完成。
2. 把 `app/mcp-client.json` 中的 `tugou` 配置加入支持 stdio 的 MCP 客户端。配置使用随桌面包附带的 Node 运行模式，不要求另装 Node。
3. 调用 `get_state` 验证连接，再调用 `list_commands` 按领域读取参数说明。

普通 `启动图构预览.cmd` 不自动启用本机控制服务。专用启动器通过单实例通道显式启用当前窗口；重复运行不会重建会话、重载工程或清空历史。客户端本身不会另开桌面窗口或自行打开工程。启用失败可再次运行启动器重试；描述文件缺失、会话离线和描述损坏会返回不同错误码及处理说明。

开发方式：先构建前端，使用 `electron . --mcp-enable` 启动桌面，再运行 `node core/mcp.cjs --session <数据目录>/mcp-session.json`。`TUGOU_DATA_DIR` 决定会话数据目录。默认文件交换目录是其 `automation` 子目录，可通过启动桌面时设置 `TUGOU_MCP_FILES` 明确指定其他目录。

## AI 调用约定

- 先查状态和对象 ID，写入携带 `expectedRevision`。这是真实内存文档版本，和保存到磁盘的版本分开；不能用磁盘旧副本覆盖当前未保存编辑。
- `list_commands {}` 默认返回全部命令的名称、说明、读写类别和必填参数名称，不展开 schema。指定 `domain` 后默认返回完整参数；支持 `scene.camera` 等子领域、`search` 名称／说明关键词搜索（空格分词取交集），以及显式 `schemas: true|false`。例如 `{"domain":"scene.camera","search":"activate"}` 可直接取得机位激活命令的参数。
- 节点位置相对父组或无限画布；图层位置相对父级；选区、笔画位置相对所属画板。查询返回父级及坐标说明，禁止把三类坐标混用。
- `batch` 最多 100 步，支持 `{"$ref":"步骤名.id"}`。只允许本地文档命令，所有步骤先在副本执行，验证成功后一次提交、一次撤销。生成、文件、像素处理不混进这个事务。
- 生成、视觉分析、本地处理、云端处理和主体识别使用稳定的 `requestId`。已提交的相同请求返回原任务；进程中断导致结果不确定时拒绝自动重发。换 requestId 表示新的操作，可能再次收费。
- `task.wait` 最多等待 30 秒；等待不会阻塞其他客户端的查询与取消命令。客户端传入 MCP `progressToken`（SDK 的 `onprogress`）时，会收到真实状态、阶段和已等待时间；已有任务提供百分比时才附加该百分比。标准通知的 `progress` 表示已发送的状态更新次数，不设置 `total`，避免把计时伪装成完成百分比。状态变化或每隔约一秒发送一次更新。
- 取消 SDK 的等待请求或断开连接，会停止本次等待轮询，不会取消生成任务；取消任务仍需显式 `task.cancel`。等待超时返回 `timedOut: true` 和最新任务状态，可继续等同一任务。会话断线后不自动重发写操作，先读取状态及任务记录确认结果。
- 图片编辑与蒙版编辑必须明确区分。`mask.fill` 只改蒙版；`paint.stroke` 必填 `target: image|mask`。异步像素操作提交前再次检查版本。
- 连接写入还需 `settingsRevision`，取 `models.status.revision`；修改立即持久化，不进入文档撤销栈。先建供应商，再加多个 Key，分别 `models.fetch` 获取列表，经 `models.set` 明确保存用途后 `models.assign` 分配默认项。获取列表不自动保存。Key 不出现在返回值、工程或请求去重日志；通过参数写入时会经过调用方客户端，也可以继续在界面录入后只按 ID 使用。
- `analysis.review` 保存审阅文本，`analysis.apply {useReview:true}` 应用该审阅；`semantic.read` 读取类别建议，人工/AI 审阅计划后才显式 `semantic.generate`。`task.retry` 只按支持任务的原快照重试，且需新 requestId；重复同一请求返回原回执。批量部分提交返回已提交 ID，不自动重新提交整个批次。
- 主体识别在本地模型未安装或内存不足时提前返回原因；识别期间文档变化则拒绝覆盖，以新任务重新执行。

批处理示例（`expectedRevision` 使用 `get_state` 的返回值）：

```json
{
  "expectedRevision": "实时版本",
  "steps": [
    {"name":"prompt","command":"canvas.create","args":{"type":"text","position":{"x":0,"y":0},"properties":{"text":"一只小猫"}}},
    {"name":"desk","command":"canvas.create","args":{"type":"config","position":{"x":400,"y":0}}},
    {"name":"link","command":"canvas.connect","args":{"source":{"$ref":"prompt.id"},"target":{"$ref":"desk.id"}}}
  ]
}
```

接着通过 `run_command` 调用 `generation.start`，指定返回的生成台 ID 和新的 requestId；查询任务后，生成结果使用当前产品既有的右侧独立节点和连线机制。

## 安全与资源约束

### 导演台调用

用 `canvas.create` 的 `type: director` 创建导演台，然后 `list_commands {"domain":"scene"}` 获取 15 条命令。`scene.object.*` 编辑物体，`scene.camera.*` 管理机位，`scene.frame.*` 保存和应用关键帧，`scene.update` 设置灯光、场景变换、背景及输出比例。坐标为 3D 世界单位，旋转为弧度；查询 `sceneObject` 或 `camera` 时必须携带所属导演台 `nodeId`，避免不同导演台的默认机位 ID 混用。

`scene.model.import` 从 `get_state.filesRoot` 内的相对路径导入模型并添加物体。普通物体与机位命令可放入批次，导入和截图不能放入批次。模型几何加载与角色姿势、动画插值沿用现有导演台实现。MCP 预览不打开导演台弹窗；界面稍后打开时读取同一份文档。

`scene.preview` 返回原生 MCP 图片，省略 `time` 使用当前状态；指定 `time` 则使用动画插值，显式 `cameraId` 可覆盖动画机位。预览不改文档；`scene.capture` 把相同画面写入素材库，在导演台右侧创建带连线的结果节点，并更新导演台输出。该操作一次撤销会同时恢复素材、节点、连线和输出引用。默认长边 1024，`maxSize` 最大 2048；场景 `size` 决定输出比例，上限内保持比例。

物体删除会从关键帧中一并移除，避免动画时重新出现；机位删除保留关键帧内已保存的机位快照。物体／机位修改不自动覆盖旧关键帧，需再次调用 `scene.frame.set`。没有关键帧时，动画沿用现有首尾机位插值行为。

调用顺序示例：`canvas.create(director)` → `scene.object.create(character)` → `scene.camera.update` → `scene.preview` → 调整 → `scene.capture` → 用返回的 `nodeId` 连接生成台。写命令始终携带最新 `expectedRevision`；异步渲染完成后再检查版本，手动编辑发生冲突时拒绝提交。

### 访问与预算

服务仅在显式 `--mcp-enable` 时启动，绑定 `127.0.0.1` 随机端口，使用每次启动重新生成的随机凭证。描述文件保存在本机用户数据目录，客户端每次读取最新会话。它是同一操作系统用户的本地自动化接口，不是多租户隔离服务。

不开放任意 JavaScript、Shell、任意 IPC、供应商私钥读取或远程文件下载。文件操作限明确的交换目录，拒绝路径穿越、目录链接和备用数据流；导出不覆盖已有文件。请求有长度、连接数、队列和超时限制。对象查询分页最大 100 条，预览最大边 2048 像素，像素编辑和整画板导出限 1600 万像素。笔画有点数和长度上限。

3D 模型文件上限 64 MiB，单次快照限 200 个物体、100 万模型顶点，背景图片限 1600 万像素；加载设置 20 秒截止时间。模型外部文件与网络纹理不允许访问，纹理应嵌入文件。快照结束释放几何体、材质、纹理及 WebGL 上下文，连续渲染不会保留一组后台渲染器。解析器本身的同步 CPU 工作不能被超时定时器抢占，超大复杂模型仍需后续隔离压力测试。

Electron 更新到 42.11.18，包含 [官方证书安全修复](https://github.com/electron/electron/security/advisories/GHSA-jr5w-w6x2-84p9)。下载运行时已按 npm 包携带的 SHA-256 校验。新增 SDK 和 Ajv 锁定版本，依赖审计结果见验收目录。

## 验收与边界

当前证据目录：`app/test-results/coverage-mcp/`；此前记录保留在 `app/test-results/pixel-budget-mcp/` 等目录。`unit.log` 是逻辑回归；`source.json` 和 `packaged.json` 是真实 SDK 客户端经过 stdio、回环服务、主进程和渲染窗口的检查；`audit.json` 为依赖审计。PNG 文件验证蒙版隐藏区域与原始图层不变，另有模型连接、3D 预览和导演台实机截图。所有供应商调用均使用本地模拟接口，不使用用户 Key 或付费额度。

验收覆盖发现、实时未保存编辑、冲突拒绝、批次回滚／一次撤销、蒙版像素、笔画、保存重开、文件边界、素材预览、本地处理、生成去重／结果节点、取消、视觉分析导入、云端结果审阅和分页。交付记录另保存包内文件一致性和用户工程数据未变的检查。

这是覆盖核心创作与 3D 静帧流程的 MCP，不等于所有菜单都已自动化。审计已登记全部 59 个桌面业务 IPC 和 14 组主要编辑动作，后续新增 IPC 若未登记会使测试失败。主要缺口包括配方局部引用、节点复制与尺寸、合并/变换/剪贴、魔棒和选区边缘、修图笔刷、叠加蒙版、参考线、3D 视频、本地组件安装、历史迁入和无窗口服务；详见覆盖表。真实主体模型、供应商长任务、复杂 FBX、大型工程、Mac 及常用 AI 客户端仍待实测。不承诺与 FigCraft 全部命令等价。

本轮检查：273 项逻辑测试通过，源码与 Windows 包各 96 项真实 MCP 检查通过，渲染错误为零，依赖审计为零漏洞。新增验证覆盖配置版本冲突、Key/URL 变更失效、隔离获取模型、密钥不回传、不进入去重日志、真实界面通知、来源详情、多角度、审阅文本应用、类别拆分、批量取消、原快照重试和跨工程拒绝。像素预算、冲突、撤销、保存重开及 3D 回归继续通过。21 个包内源文件／构建文件逐项一致；25 个用户工程与连接文件交付前后哈希一致。当前交付为 `release/coverage-mcp`，未重启用户窗口。
