# 开发预览与安全热更新

入口：项目根目录双击 `启动土狗开发预览.vbs`，或在 `app` 下运行 `npm run dev`。首次从旧预览切换须先保存并关闭旧窗口。以后保持开发窗口打开即可；重复打开入口会聚焦同一进程。

开发预览沿用 `app/preview-data` 中的工程、素材和模型配置，构建输出位于被 Git 忽略的 `app/.dev-preview/ui`。原有打包预览入口仍保留。启动需要本机 Node 和已安装的 app/node_modules，不是面向终端用户的安装包。

## 更新行为

| 修改 | 行为 |
| --- | --- |
| renderer 样式 | 原位替换样式表，不重建页面，保留输入焦点 |
| renderer JS/JSX/HTML | 构建成功后，在安全时机保存主进程内存检查点，再刷新渲染器 |
| core、主进程、preload、构建配置与依赖清单 | 显示重启提示，保留当前运行版本；不会强制退出 |
| 构建错误 | 保持旧界面和编辑内容，展示错误；修正后自动再构建 |

JS 更新检查点包含当前未保存工程、dirty 标记、撤销/重做栈、当前工作区与图层选择、已消费的任务结果。不会调用工程保存，不会将未保存修改写入原稿。设置子页、画布侧栏页签与侧栏滚动位置同时恢复。

输入框正在编辑、鼠标拖动、弹窗与选择浮层打开、任务正在运行时会暂缓 JS 更新。字体与工具工作区需先完成编辑并切换工作区；合成区需结束绘画/选区等编辑并回到移动工具。画笔异步提交、图像导入与导出完成前也不会更新。CSS 不重建这些组件。

这不是 React Fast Refresh，也不承诺任意组件局部状态可以跨重建存活。通过检查点保存工程状态、通过等待保护局部草稿。超过 64 MiB 的编辑现场会保留原界面并提示先保存后重启，不截断撤销记录。若替换代码在初次挂载时出错，主进程保留检查点，修正代码后恢复；检查点不覆盖整个应用进程崩溃或断电。

## 边界与验证

- 热更新仅在未打包应用且显式开发环境变量开启时启用。普通运行不显示入口、不启动监听，拒绝应用热更新请求。
- 没有新增 HTTP 开发服务器、远程调试端口或 MCP 写入命令；沿用原 IPC 来源校验、渲染器沙箱与隔离。供应商 Key 不进入检查点。
- 文件在临时目录构建，复制前保留旧构建用于 I/O 失败回滚。单个开发主进程存活期间保留检查点。
- 隔离桌面验收脚本：`app/test/dev-preview-desktop.cjs`，使用独立源码副本和 profile，不修改用户工程，不调用收费生成。
- 逻辑验收：`node --test test/dev-preview.test.cjs`；全量资源受限环境用 `node --test --test-concurrency=1 test/*.test.cjs`。
- 证据：`app/test-results/dev-preview/desktop.json`、同目录截图、`unit-all.log`；普通启动回归：`app/test-results/settings/desktop.json`。
- 当前实测为 Windows。Mac、超大工程长时压力和断电恢复未验证，不作为本次完成范围。
