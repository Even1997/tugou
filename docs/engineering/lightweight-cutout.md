# 轻量主体抠图与 MCP 验收

## 变更与验收口径

目标是让资源不足的机器可实际完成主体抠图，并保持 UI、MCP、任务重试和保存结果一致。验收要求：正确使用所选模型；真实推理输出尺寸与原图一致、RGB 不变、已有透明度不增加；取消清理临时文件；主体选区保存至所属画板；精细模型不绕过资源保护。

沿用现有 ONNX/Pillow/NumPy 工作进程，新增 U²-NetP CPU 适配，没有引入整套 rembg、PyTorch 或在线调用。普通主体使用轻量模型；精细 BiRefNet 仍可手动选择。AI 主体选区优先使用可运行的精细模型，否则明确显示并使用已安装的轻量模型。

模型标识、文件哈希和内存预算集中在 `app/runtime/cutout-models.json`，由后端与 Python 共用。原精细预算不降低；轻量预算为 1 GiB 可用物理内存、Windows 2 GiB 可用提交空间，另计源图缓冲。MCP `image.process` 的 cutout.model 枚举为 `birefnet` / `u2netp`；缺省仍为 birefnet，兼容已有调用。工具新会话默认选择轻量模型。任务快照、重试及素材 toolResult 保留模型名。

- 许可证、固定源码版本和模型来源保存在 `app/runtime/component-notices/`；组件安装同步复制授权文件。

本机现有 `D:/CanvasStudioRuntime/segmentation/` 已补充验证后的轻量权重。正式按需安装的抠图包包含精细与轻量两种权重，模型总下载约 495 MB，另有 Python/推理依赖，并非只下载 4.6 MB。模型不内置到应用安装包。下载后推理离线运行。

## 实测证据

- `app/test-results/cutout-repair/unit-final.log`：44 项相关单元/任务/MCP 回归通过，覆盖内存预算、取消、安装失败不激活、模型丢失、任务重试及参数保留。
- `app/test-results/cutout-repair/native-report.json`：13 项真实本地检查。白底、灰底、花纹背景、已有透明度共 4 张样例，尺寸及 RGB 完整保留，输出有主体和透明区域；取消后临时文件清理。
- 512×768 样例整条处理链约 0.8 秒；实际工作进程峰值工作内存 347,357,184 字节（约 331 MiB），峰值提交内存 1,246,937,088 字节。此为小图样例，不代表大图或所有设备。
- `app/test-results/cutout-repair/desktop-report.json`：10 项隔离桌面与真实 MCP 检查通过，覆盖模型选择、处理、主体选区、保存重开、结果元数据和渲染错误。
- `app/test-results/cutout-repair/desktop-cutout.png`：实际原图/结果对比；模型下拉、状态和质量限制均可见。
- 独立前端构建输出 `app/test-results/cutout-repair/dist`；未替换运行中的用户窗口。

本轮曾对精细模型关闭 CPU 内存池与图优化进行有界探测，实际进程仍超过 6 GiB 私有内存后终止，因此没有将该实验配置或放宽内存门槛带入产品。

## 结果边界与质量自评

真实婚纱样例显示轻量模型能移除大面积背景，但发丝、薄纱边缘有柔化和白边，不能称为精细抠图等价替代。需保留精细模型或蒙版人工修整。Mac 原生环境、更多主体类别、精细模型和大图长时压力仍待验。本次未使用付费 API、未修改用户工程、未发布。
