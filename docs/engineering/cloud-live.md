# 局部修改、蒙版羽化与真实扩图验收

本轮仅改实际桌面项目的云端编辑/扩图，不发布、不修改用户工程或供应商设置。验收目标：手绘区域可执行修改；涂画外 RGBA 严格不变；扩图保留原图坐标与像素；错误尺寸保留原始返回且不自动重试；UI 与 MCP 共用参数。

## 参考与改动

- [IOPaint 合成保护区](https://github.com/Sanster/IOPaint/blob/main/iopaint/model/base.py)：生成结果按蒙版与原图合成。
- [IOPaint 扩图初始化](https://github.com/Sanster/IOPaint/blob/main/iopaint/model/helper/g_diffuser_bot.py)：边缘颜色复制，为新增区域提供参考。本项目用已有 Sharp 的 extendWith: copy 实现，不引入其 Python/模型依赖。只参考思路，未复制第三方源码。
- [Fooocus 蒙版与局部合成](https://github.com/lllyasviel/Fooocus/blob/main/modules/inpaint_worker.py)：参考其区域处理与软边合成思路，本轮未实现自动裁切推理或接入其模型。

`mask-feather.cjs` 是前后端共用的两遍近似距离变换，向内柔化而不扩展选区。默认 0 完全保留旧结果。半透明蒙版、黑白亮度、反转、孔洞均保留保护语义；全图选择不因画布边界变淡。预览按显示比例近似显示，正式处理在原图分辨率执行。内存预算增加辅助数组开销。羽化后全空在网络请求前拒绝。

扩图上传画布的新增区域由原图边缘颜色延展，透明边缘先以白色合成作为参考；输入画布原图矩形和最终输出仍恢复原始 RGBA，独立透明蒙版界定可修改区。此初始化是模型参考，不是扩图结果，也不承诺模型完全服从。

UI 的“蒙版规则 → 蒙版向内羽化（px）”支持 0–1000 整数；小区域建议小数值，大羽化可能保留待移除对象。MCP `cloud.process` 的 `settings.feather` 已支持素材蒙版，校验在共享设置函数中执行。任务元数据、重新打开工程和预览均保留。

## 实际验证

证据目录：`app/test-results/cloud-live/`，可直接打开 `效果与验收.html`；界面证据 `app/test-results/cloud-paint/`。

| 验证 | 结果 |
|---|---|
| Node 回归 | 40/40：上传蒙版、前后端共用算法、透明混合、反转、空蒙版、尺寸异常、本地恢复等 |
| 隔离 Electron 与 MCP | 27/27：真实指针涂画、擦除孔洞、羽化 UI=3/MCP=5、保存恢复、外部像素保护、浮层无横向裁切、深浅主题、960×720、6MP 坐标 |
| 真实局部修改 | 当前 `gpt-image-2.5-sunburst`，56.2 秒，花束变向日葵；1024×1536；1,506,300 个保护像素 RGBA 相同 |
| 真实扩图修复前 | 54.7 秒，尺寸与原图保护通过；新增区域存在不自然透明过渡，画质不合格。查看器显示黑色实际是透明通道，不是黑底像素 |
| 真实扩图修复后 | 59.0 秒，1024×1536；884,736 个原图像素相同；688,128 个新增像素中非不透明数从全部降为 0；背景改善，袖口/边界衔接仍有偏差 |
| 缓存返回本地羽化 | 对真实修改结果做 12px 羽化，保护像素仍相同；未再次调用模型 |
| 单独性能 | 2048×3072 / 24px 羽化约 468ms，辅助数组约 30MiB；不含图像解码/编码和模型耗时 |

真实请求共 3 次，使用实际 CloudTaskService → Images API → 保护区合成链；MCP 桌面测试用回环模拟供应商，不能混为真实 MCP 供应商端到端验证。未读取回显 Key；连接通过原有加密存储在进程内使用。真实测试工程位于独立目录；已提交任务不会自动重发。`test/cloud-live.cjs` 需显式 `--run-live --case=edit|extend|extend-context`，同证据目录禁止重复提交；测试原图依赖本机验收素材，未纳入正式安装包。

当前结论：代码修复及局部修改可交付，扩图美术验收没有全部完成。阻塞来自当前生成模型在边界外补绘的几何偏移；简单模糊或背景填白不能修复错位，直接采用模型整图又会破坏原图像素保护。下一步应使用更多复杂构图对比具备可靠 inpaint 能力的模型，或另做可选择的边界配准/人工复核；不能将该限制包装成已修复。Mac 实机、其他供应商和最大图仍待。
