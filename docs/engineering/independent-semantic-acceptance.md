# 独立类别拆分验收

对照旧版 `atelier-semantic-acceptance.md` 的行为规格，本批接入语义类别方案、视觉建议、逐类黑白蒙版请求、原像素提取和对齐入层。没有把包围框裁切或透明岛拆分当作语义分割，也没有接入旧应用实现。

## 行为与完成定义

- 顶部“AI 类别拆分”允许每行填写一个对象，最多 12 类；每项最多 400 字，拒绝重复和空方案。类别方案按来源素材保存在工程中，可编辑、保存或随提交保存。
- 识别使用共享连接中的视觉分析模型；建议落盘但不自动覆盖方案，用户明确读取后编辑。来源切换/离开页面时迟到读取不写入新上下文；取消不覆盖方案，较早完成的建议仍可读取。图片里的命令作为图像内容处理。
- 每类独立提交 Images edits，以原图和对象描述请求不透明黑白灰蒙版；各类状态/取消/失败/重新请求独立。明确点击“重新请求模型”才再次请求，可能再次计费；固定原素材与参数，连接改变时拒绝悄悄改用另一模型。
- 本地输出保留原图的 RGB（含透明像素中的颜色），Alpha 为来源 Alpha 乘蒙版覆盖率。保留全画幅、孔洞和灰边，不补画遮挡部分。彩色、透明、尺寸不同或缺少明确黑/白区域的蒙版保留原始返回并进入审阅，不发布拆分素材。
- 每类结果独立入库、撤销和恢复；“对齐入层”明确选择来源图层，复制其分组及几何变换，不复制其调整/特效/蒙版，不修改或隐藏原图层。相同结果与同一来源实例重复入层去重；多个来源实例可明确分别选择。
- 完成的类别草稿与图像结果分开读取，避免把文字识别结果当作图片入库。原始图审阅、明确缩小对齐及离线恢复沿用云端工具规则。

实现主要为 `semantic-plan` 参数/视觉提示词、`SemanticService` 识别与逐类提交、`cloudSplit` 原生像素处理和 `SemanticControls` 顶部组件。共用 `CloudTaskService`、任务面板、结果事务和模型设置；无 MCP、无新旧持续同步。
