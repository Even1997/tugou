# 云端入口收敛与自由涂画修改区域

## 范围与完成定义

工具页可见入口由 23 项收敛至 20 项。云端只保留 AI 局部修改和 AI 扩图，去掉云端增强、创意放大、AI 类别拆分的导航及下拉入口。旧结果继续显示中文工具名、可查看和导出，不激活撤下工具。底层历史处理器和现有 MCP 协议仍保留兼容，本轮没有声称删除这些 API。

完成标准：用户能在原图上涂画/擦除任意区域；支持清空与撤销重做；默认不提交全图；保存等原图尺寸蒙版；缩小预览不改变笔迹坐标；应用与取消不触发模型请求；UI/MCP 共用蒙版处理并逐字节保留零覆盖区域；保存重开资源完整。

## 用户流程

1. 选择原图及 AI 局部修改，点击“涂画修改区域”。
2. 在原图上涂蓝色区域；擦除表示恢复保护。笔刷大小按原图像素计算，可撤销、重做或清空。关闭/取消放弃本次草稿。
3. “应用修改区域”将蒙版保存为当前工程素材并选中它，不调用模型；填写修改要求，再点击“提交云端”。工程仍按应用既有保存机制保存。

空蒙版不能应用；未选择蒙版不能提交。仍保留矩形、蒙版素材、已有画面选区入口。重新打开涂画窗口可以继续编辑当前蒙版；取消不覆盖原蒙版。切换原图会清除旧蒙版选择。涂画素材可在素材库复用，MCP 用 `cloud.process` 的 `maskMode: asset`、`maskId`、`maskChannel: alpha` 复用同一蒙版。

## 实现边界

使用现有 FormDialog、Button、NumberField、loadOriginal、pngBytes、storeRaster 和云端像素合成链路。新编辑器仅维护矢量笔迹和一张最长边 1024 的预览蒙版，按帧合并重绘；应用时才按源图尺寸栅格化与编码，不逐笔编码整图。单次草稿限 20,000 个点，达到后提示先应用再继续编辑。已有蒙版根据现有透明度/亮度/反转规则转换；导出不把蓝色提示写入原图。

导出检查按 64 行读取，避免额外创建整个图像的 JS 像素副本。仍有原尺寸 Canvas 内存开销；本轮实测至 2048×3072，不能据此宣称 100MP 编辑已完成压力验收。

应用时检查当前工程快照与来源，拒绝覆盖发生变化的编辑现场。原图、已有蒙版、结果均保留，取消不落入工程。模型只负责生成候选图，最终结果仍使用本地蒙版合成，零 alpha 位置保留原 RGBA。

## 验证

证据目录：`app/test-results/cloud-paint/`。

- `unit.log`：37 项云端准备状态、参数、任务、像素、语义历史兼容与本地图像回归通过。
- `desktop-report.json`：24 项真实 Electron UI、鼠标笔迹与 MCP 检查通过；包含空蒙版拒绝、擦除孔洞、清空/撤销/重做、取消、切换工具保留参数、切换来源清除蒙版、保存重开、旧结果查看。
- 64×48 确定性样例检查涂画与擦除几何；UI 和 MCP 各提交一次局部修改，逐像素比较全部零覆盖区域，RGBA 完全一致，涂画区确实发生变化。
- 2048×3072 人物图检查缩小预览、源尺寸导出及笔迹位置；该检查不请求模型。
- 深色窗口、960×720 浅色窗口实际截图检查：`paint.png`、`paint-portrait-light.png`、`edit.png`。
- 独立前端构建成功，renderer 错误为 0；测试使用隔离工程和本机 HTTP 模拟供应商，仅 3 次本机请求，不读取真实 Key，不收费。

模拟结果用于验证蒙版和保护区，不证明真实 AI 修改质量或供应商兼容性。未发布、未重启用户实例。
