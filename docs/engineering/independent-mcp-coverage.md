# MCP 功能覆盖对照

结论：核心创作链路可用，仍未覆盖平台全部功能。当前目录为 135 条命令，其中字体 22 条，顶层仍为 7 个工具。命令数量不是功能完成率。下面历史验收记录保留原口径；最新变更见本节。

## 字体显式发布

字体工作台顶部新增发布/更新发布。无当前编译结果时自动编译再发布；已完成结果直接发布。仅已发布字体进入选择列表，预览或字形修改不替换已发布版本。发布按fontRevision检查、requestId去重、核对当前源版本和TTF摘要；失败保持旧发布。已有文字保留内容寻址资源版本，更新发布只影响后续选择。MCP新增font.publish，共135条命令，字体22条。

调用流程：font.build(mode:draft) → task.wait → font.project.get → font.publish({projectId,fontRevision,requestId,jobId}) → font.library → font.face → layer.update。draft编译允许部分字符；发布到图构不代表已审核字形身份或风格，不安装系统字体、不上传。仅当前已发布jobId可新取得face，已有文档继续加载固化资源。

## 字体搜索与实际应用

font.library 列出 Windows 系统字体（family/name/aliases）和图构字体项目（ready/jobId）；font.face({projectId,jobId}) 将已完成的TTF校验并缓存到受控资源目录，返回 {fontFamily,fontResource}。把结果传给 layer.update.patch 或 layer.create.properties 即可使用。字体无需安装到操作系统，保存重开与画板导出均加载相同资源。fontResource=null 可清除，直接修改 fontFamily 也会清除旧自定义引用。未生成、校验失败和越界路径拒绝。命令不会执行字体编译或付费请求。

前端使用现有 Ant Design Select 样式、分组与虚拟列表；API 对照 [官方 Select 文档](https://ant.design/components/select/)。

验证：58项相关Node、21项最终包字体桌面/SDK与96项原MCP回归通过；详见 app/test-results/font-picker。

## 启动重连与高频编辑补齐

- 普通预览和 MCP 启动入口均传入 `--mcp-enable`。显式启用后，数据目录记录 `mcp-enabled.json`；后续直接启动同一数据目录的应用也恢复 MCP。未启用的全新独立数据目录仍不默认开放。
- 每次 MCP 调用重新读取当前会话描述。读取请求遇到启动窗口期可在3秒内重新连接；写操作、生图及任务重试不自动重发，避免不确定结果造成重复写入或扣费。会话仍只绑定127.0.0.1并校验随机凭证。
- `image.fillSelection({id,mode:"fill"|"clear",color})`：编辑图片原始像素空间中与画板选区对应的部分，保留蒙版与原素材；填色必须明确颜色。
- `layer.replaceImage({id,assetId})`：清除该图层旧bitmap，替换素材，保留显示框尺寸、位置、旋转、蒙版、层级及特效。新图适配原显示框；这与界面按原图比例替换的策略不同，调用者需明确所需比例。
- `layer.merge({ids})`：同一画板内相邻顶层普通混合图层/分组合并；只给一个id即栅格化。返回新id，单次撤销恢复原可编辑对象。拒绝锁定后代、跨画板、不相邻、外部剪贴/蒙版依赖及未裁切画板；原图/蒙版与输出受1600万像素预算约束。
- `preview({artboardId,id,mode:"overlay"|"original"})`：分别查看红色蒙版叠加及忽略指定层蒙版的合成结果；不修改文档、蒙版开关和撤销历史。需指定同画板内已有蒙版的图层。

验证：37项Node检查、27项最终包新增SDK/桌面检查、96项最终包原有MCP回归通过，零渲染错误；8项包内摘要一致。同一个stdio客户端跨窗口关闭、无参数重启仍可读取新会话。当前用户旧窗口仅恢复连接，未重启或修改工程。

像素检查：选区填色/清除与蒙版预览按区域取样；单层栅格化逐像素一致；含半透明层合并最大RGB偏差1/255、Alpha一致，来自PNG的8位透明度取整，不宣称逐字节相同。所有新增写操作均验撤销/重做、失败不改文档和保存重开。

本机Codex仅更新图构MCP条目的版本路径，配置已备份。新桥接程序需要客户端重新加载配置；应用重启时旧stdio客户端仍按稳定会话路径重新连接。配置字段依据[官方MCP文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)。

证据：`app/test-results/reconnect-editing/packaged.json`、`package-integrity.json` 与 `app/test-results/mcp-editing-regression/packaged.json`。仍待自由变换/精细修图、无窗口运行、Mac与小时级大工程压力；不是全功能完成。

## 审计范围与依据

- 实际项目为 `app/` 独立桌面版；历史 `web/`、供应商模型内部能力不计入桌面覆盖率。
- 逐一登记 `app/desktop-main.cjs` 的 **59 个业务 IPC 入口**，归为 16 组；另外对照 14 组主要前端编辑动作。原生媒体协议不是业务命令。
- 可机读清单：[mcp-coverage.json](mcp-coverage.json)。测试要求每个业务入口恰好登记一次，清单引用的 MCP 命令和源码必须存在。增加 IPC 后不更新清单会使检查失败。
- 前端动作对照是源码人工审计；这项自动检查不证明所有按钮、参数组合或平台行为已验收，不据此计算百分比。
- “已覆盖”表示提供了相应业务入口或等价调用路径；不表示每个真实模型、所有格式和参数组合都已测过。

## 本轮直接补齐

| 能力 | 新命令 | 行为 |
|---|---|---|
| 供应商 | `models.provider.create/update/delete` | 一个供应商只允许一个 URL；更改地址使所属 Key 模型及受影响用途失效 |
| 多 Key | `models.key.create/update/delete` | 独立命名和模型目录；密钥仅写入加密存储；修改 Key 只清空自己的目录及用途 |
| 测试与获取模型 | `models.test`、`models.fetch` | 使用指定已保存 Key；不生图，获取列表不自动保存、不猜测用途 |
| 模型和默认用途 | `models.set`、`models.assign` | 明确标注模型用途，分别选择图片、分析、文本、视频和音频默认项；可清空用途 |
| 素材 | `asset.details`、`asset.delete` | 查看真实生成提示词和来源；删除引用中的素材会整批拒绝，无引用移除可撤销，不删除磁盘原文件 |
| 任务重试 | `task.retry` | 复用工作流、本地图像、云处理原快照；拒绝其他工程的任务；新的 requestId 表示新的重试 |
| 云端批量 | `cloud.batch`、`cloud.cancelBatch` | 最多 64 张，返回批次和任务 ID；部分提交保留已提交回执，重复请求不再次提交 |
| 类别拆分 | `semantic.analyze/read/generate` | 识别类别、读取方案，允许修改方案后按类别拆分；返回各任务 ID |
| 多角度 | `generation.angle` | 调用原多角度服务和来源绑定检查，保存真实镜头提示词和来源关系 |
| 分析审阅 | `analysis.review` | 保存改写后的模块文本、启用及全局设置；`analysis.apply {useReview:true}` 应用保存的审阅 |

共新增 20 条。现有 `canvas.update` 另外补齐输入职责、镜头要求、不拼上游文本、首尾帧、视频声音/水印/扩展参数、音频指令和文本结果编辑。

## 配置调用顺序

1. `get_state` 取得当前文档 revision；`models.status` 取得连接配置的 revision。
2. `models.provider.create` 添加供应商名称与唯一 URL。
3. `models.key.create` 为同供应商添加一个或多个 Key；已有 Key 可留在界面录入，AI 只使用它的 ID。
4. 对每个 Key 分别调用 `models.test`、`models.fetch`。
5. `models.set` 保存确认过的模型及用途，再用 `models.assign` 指定各用途默认模型。

配置操作还需 `settingsRevision`，值来自 `models.status.revision`。修改立即持久化，返回新的 `settingsRevision`，不进入工程撤销栈。版本过期拒绝写入；探测期间配置变化则丢弃结果。修改成功通知既有界面更新；已打开但尚未保存的旧配置草稿仍受原配置版本检查保护。

返回值不包含 API Key，Key 也不进入 MCP 请求去重日志或工程文档。若通过 MCP 的 `apiKey` 参数写入，该值会经过调用方客户端，客户端自身是否保存工具参数不由图构控制；界面录入后仅按 ID 操作可避免在 AI 对话中传入密钥。不会修改客户端全局配置。
