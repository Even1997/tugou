## 更新机制

使用固定 GitHub Releases 源 Even1997/tugou 和 electron-updater 6.8.11。前端不接收任意更新地址、可执行文件路径或发布令牌。当前 app/package.json 与根 VERSION 统一为 0.8.1，没有打 tag 或发布 Release。

安装版启动后延迟检查，一天最多自动检查一次；手动检查不受此限制。自动下载默认关闭，安装始终需要用户点击确认。进度来自 updater 的实际事件，下载校验 SHA512，失败不显示为“已是最新版”。预览／便携版说明需要安装版并提供发布页入口。

安装前两次检查未保存修改、任务、主体识别及进行中的本地/MCP 编辑，等待工程、字体、设置和任务记录落盘。MCP 会话标记更新维护状态，stdio 客户端主动退出释放程序，随后安装并重启；新进程恢复服务。普通退出不会自动安装。Windows 安装器使用 customCheckAppRunning，等待仍运行的进程退出，超时则拒绝安装，不强制结束进程。

交付包：app/release/settings-center。预览启动脚本和已有 MCP 配置指向新版。安装包未签名；Mac 已配置 DMG + ZIP，签名、公证及 Mac 实机升级待验。

## 验收边界与事件记录

仓库本轮核实仍为私有且无 Release。真实下载／安装验收使用本机 HTTP 发布源和独立 appId、程序名、安装目录及数据目录；没有对外发布，不能替代公开 GitHub 源的上线验收。

首轮 NSIS 测试只隔离了 appId 和目录，仍使用 Tugou.exe，发现默认安装器在 PowerShell 检查不可用时会按程序名处理同名进程，原预览可能因此被关闭。磁盘工程仍在；没有事前内存快照，无法确认未保存内容是否受影响。已停止该轮、改为独立程序名，移除旧测试安装，并为生产安装器增加不强制结束进程的保护及真实存活验证。此事件不能用后续测试通过掩盖，原工程未保存状态仍需用户核对。

待验：公开 GitHub Release 从检查到升级、Windows 签名／SmartScreen、Mac 签名与实机、系统通知权限、多 DPI、长期大工程压力、专业编辑器全量翻译。尚未执行 git commit/push 或发布操作。

## 模型直选与通用 MCP 增补

模型用途行已改为可搜索下拉，使用原有带 revision 的供应商保存 API；更改后触发连接刷新事件，过期状态拒绝写入并重新读取。MCP 导出使用同一 command / args / env 数据生成通用 JSON、VS Code JSON、Codex TOML，可预览并逐字段手动填写，不读取或导出供应商 Key 与会话 token。

协议依据：[MCP stdio](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)、[VS Code 配置](https://code.visualstudio.com/docs/agents/reference/mcp-configuration)。JSON 配置外壳是客户端约定，不能称为所有客户端统一的配置规范。

28 项相关 Node 检查；29 项桌面 / SDK / 重启检查与 5 项包内文件一致性检查，证据 test-results/settings-connections。独立测试配置使用虚构 Key，未调用付费模型。仅本机 Windows 完成验证；第三方客户端安装界面和 Mac 仍待。
