# 图构双端交付与验收

目标为 Windows x64、macOS Apple Silicon arm64 和 Intel x64。共用独立版组件、业务逻辑、工程格式、素材和直连模型 API。双端指两种桌面系统，不包含账户云同步。

当前结论：双端基础已写入，Windows 本批验收通过；macOS 尚无构建和真机证据，完整目标未完成。Windows 的逻辑测试不能替代 Mac 系统行为测试。

按当前交付安排，Mac 实机作为独立验收清单；本机继续完成 Windows 可验证事项，不以 Mac 未验宣称 Windows 失败。最新 Windows 证据见[抠图与复杂工程验收](independent-local-final-acceptance.md)。双端交付仍须下表 Mac 项全部验证，Windows 正式安装更新另行受当前窗口保护和本机验收门禁约束。

## 构建与验证

在 `app` 目录执行：

```sh
npm ci
npm run build
npm test
npm run test:desktop
npm run pack:dir
```

- `test:desktop` 使用系统临时目录创建隔离 profile，不依赖 D 盘或真实用户工程；报告位于 `test-results/platform-<platform>.json`。
- `npm run dist:win` 构建 x64 NSIS；卸载配置保留 appData。实际安装/升级尚未验证。
- 在 Mac 执行 `npm run dist:mac`，目标为 arm64/x64 的 DMG 与 ZIP。Windows 调用此命令会明确拒绝，不伪称能产出已验收 Mac 包。
- macOS 本地开发可用 `npm start` 或 `sh 启动图构.command`；双击脚本还需要本机可执行权限。正式用户使用应用包。
- 正式 Mac 发布须配置开发者签名与公证凭据，并在各芯片环境运行桌面及像素回归。签名身份需保持稳定以验证 Keychain 访问。凭据不写入仓库。
- 当前 Windows 目录包验证使用 `--config.win.signAndEditExecutable=false`，仅跳过测试候选的可执行文件装饰/签名；未将这一配置写入正式发布默认值。
- `test/packaged-desktop.cjs <应用可执行文件>` 从外部以本机临时调试端口验收目录包；正式应用不包含 QA 后门、测试驱动或自动打开的调试端口。

运行时许可证正文由构建生成到 `dist/THIRD_PARTY_NOTICES.txt`，随应用打包。应用包只包含独立运行代码与编译产物，不带用户工程、测试资料或旧产品源码。
